# Managed tool resources

Mobius release packages contain a reviewed, target-specific command-line tool bundle in this
directory. Generated platform binaries are intentionally excluded from Git; the release workflow
recreates and verifies them on the matching native runner before Tauri packages them.

The installed application does not download or silently update tools at runtime. A normal release
therefore works without putting Android tools or libimobiledevice on the user's `PATH`.

## Bundled components

Each supported target contains:

- Android Debug Bridge (ADB) 37.0.0, scrcpy 4.1, and its matching `scrcpy-server`, taken from the
  same official scrcpy portable distribution. The Windows target also keeps the required adjacent
  runtime DLLs from that archive. Preparation independently verifies ADB and its Windows DLLs
  byte-for-byte against the exact target Android Platform Tools 37.0.0 archive.
- AAPT2 9.4.0-15978811 from the official Google Maven artifact, including its complete `NOTICE`.
- FFmpeg 9.0.1, built from the locked upstream source as a minimal LGPL-2.1-or-later command. GPL,
  nonfree, network, and external codec components are not enabled. The Windows build applies the
  published native-timing patch, locks its compiler version, and rejects external MinGW runtime
  DLL imports; its effective configuration, compiler identity, patch, and import list are retained.
- go-ios 1.3.2-mobius.1, built from the locked go-ios 1.3.2 source with the published Mobius patch.
  The patch records the exact version and changes host forwarding and optional screenshot-server
  listeners from all interfaces to `127.0.0.1`. It is built with Go 1.26.5 and ships the Go runtime
  and standard-library license.
- The first-party Mobius SSH/SFTP helper, built with CGO disabled. It implements the exact
  password/private-key command, single-file SFTP, and loopback `-L`/`-R` operations generated by
  the application, using locked `x/crypto/ssh` and `pkg/sftp` modules. Identical reviewed copies are
  installed as `ssh` and `scp`, so jailbreak workflows do not depend on system OpenSSH or `PATH`.

The scrcpy portable components retain the exact licenses and notices for FFmpeg 8.1.2, SDL 3.4.12
and its embedded third-party portions, libusb 1.0.30, dav1d 1.5.3, target-specific zlib, and the
MinGW-w64 runtime on Windows. Static-link targets also have complete source and relinking material
in the Release companion archive.

go-ios is the primary host adapter for iOS discovery, information, app listing and installation,
screenshots, bounded logs, and safe USB forwarding. Locally configured libimobiledevice programs
and `iproxy` remain optional compatibility fallbacks. USB forwarding accepts only the exact bundled,
loopback-hardened go-ios build; an arbitrary configured `ios` executable is never trusted for that
listener.

Frida Server is not bundled. It remains a user-supplied, device-ABI-specific payload, and Mobius has
no host Frida CLI dependency.

## Generated layout

```text
tools/
  README.md
  THIRD_PARTY_NOTICES.txt
  macos-aarch64/          # generated
  macos-x86_64/           # generated
  linux-x86_64/           # generated
  windows-x86_64/         # generated
```

Every generated target directory contains the executables, any required adjacent runtime files,
`scrcpy-server`, a complete `manifest.json`, and a `licenses/` tree. The manifest records the target,
bundle revision, component versions/licenses, and the size, SHA-256, component ownership, and
executable flag for every shipped file.

## Reproducing a target bundle

`packaging/toolchain.lock.json` is the reviewed source of truth for versions, HTTPS download URLs,
archive sizes, SHA-256 values, source commits, patch path, and FFmpeg configuration. On a native
build environment, replace the example target as needed:

```bash
python3 scripts/prepare_tool_bundle.py \
  --lock packaging/toolchain.lock.json \
  --target macos-aarch64 \
  --output src-tauri/resources/tools/macos-aarch64

python3 scripts/verify_tool_bundle.py \
  --lock packaging/toolchain.lock.json \
  --target macos-aarch64 \
  --root src-tauri/resources/tools
```

Windows uses the equivalent `python` commands from the release workflow's MSYS2 MINGW64 shell.
The prepare script only accepts a matching `tools/<target>` output directory. It verifies exact
download size and SHA-256 before extraction, rejects links/devices/path traversal, enforces member
and expansion limits, extracts source licenses only from explicitly locked regular members,
builds FFmpeg, go-ios, and the Mobius SSH/SFTP helper from source, gathers licenses, and writes the
per-file manifest. The verify script rejects unexpected files and archives, checks hashes,
permissions and target architectures, then runs native version smoke tests and verifies the matching
scrcpy Server payload.

macOS nested Mach-O files are signed before the outer application bundle; because signing changes
their bytes, the release workflow refreshes the manifest and performs the full verification again.
Do not manually place an unpinned executable in this directory or bypass the lock/prepare/verify
steps.

## License and source delivery

`THIRD_PARTY_NOTICES.txt` is the project-level attribution summary. Each generated target also ships
the exact upstream license/NOTICE texts, scrcpy dependency provenance, FFmpeg configure flags, the
Go runtime license, go-ios patch/module list, and collected Go dependency license files.

Every Release additionally contains
`Mobius-Device-Lab_<version>_third-party-sources.tar.xz`, produced by
`scripts/create_third_party_sources.py`. It carries the exact complete scrcpy and portable
dependency sources (including target zlib and Windows MinGW-w64 runtime), FFmpeg, go-ios, the
Mobius SSH/SFTP helper's locked modules, and Go sources; helper source/tests, the patch, licenses,
target ADB notices, linkage index, lock, and build/relink scripts are included too. Its own
`SHA256SUMS.txt` authenticates every other member. The archive and all
installers are included in the release-level `SHA256SUMS.txt`.

Windows still needs Apple Mobile Device USB drivers/services for iOS USB access. Linux still needs
working usbmuxd and udev permissions. Device trust, Developer Disk Images, jailbreak SSH/AppSync,
and device-side package installers are system or authorized-test-device requirements and cannot be
embedded as ordinary desktop resources.
